# YiHe 编程开发辅助包（pkg-dev）

> 版本：**3.0.0** · 命名空间：**开发** · 行业：软件开发 · owner：developer · tier：**pro**（license_required）
> 用途：开发者用 `yihe_reason` 在「开发」命名空间上做**编程决策辅助**。
> **v3.0 把 YiHe 自身认知理论（意合/关系编织/激活扩散/势态推演/辩证推演/留白/确认网关/
> 学习闭环/三态逻辑/滚动规划/类比推理…）作为方法论维度编入包内**——
> 让"如何用 YiHe 辅助编程"本身可被推理，理论×编程双链自动参与决策。
> **姊妹子包**：`pkg-dev-ts`（TypeScript/Node 全栈）、`pkg-dev-py`（Python 全栈）——各自 README 见同目录。
> **执行层接入**：决策可经 `yihe_exec` plan→advance→report 滚动执行（实测通过，见 §七）。

## 二、使用流程（会话内）

```text
1. 导入：yihe_pack  op=import  content=<yihe-packs/pkg-dev.json 的内容>
   （v2→v3 增量也可：仅传新增 32 意象+50 关系+10 脚本，同 id/同命名空间=合并）
2. 激活：yihe_pack  op=activate  id=pkg-dev
3. 推演：yihe_reason  question=<开发问题>  input=<补充上下文>  namespace=开发
```

激活后命名空间自动切到「开发」，此后 `yihe_reason` 默认在该关系网上推演；
管理操作自动记入 `yihe/audit`。

## 三、设计说明：意象→关系→脚本如何联动

- **v1 核心链**：`需求不明确→需求变更→技术债→削弱交付`；`模块化→削弱耦合→支撑可维护`；
  `测试→削弱缺陷/回归→支撑质量`
- **v2 实战链**：`认证/授权→支撑安全`；`漏洞→削弱安全→导致泄露`；`缓存/索引→削弱延迟`；
  `事务→支撑一致性`；`接口设计/版本管理→支撑兼容性`；`灰度→支撑上线/回滚`；`容灾→支撑可用性`
- **v3 理论链（YiHe 认知方法论）**：
  - 认知：`意合 → 关系编织 → 激活扩散 → 激活度/路径推演 → 候选集 → 势态推演 → 辩证推演 → 正反合`
  - 决策：`语境场 → 随境赋义`；`语境修剪 → 语境场`；`留白 → 确认网关 → 暂停确认执行`
  - 进化：`学习闭环 → 反馈回报 → 经验库 → 记忆分层 → 脚本池`；`类比推理 → 经验库/脚本池`
  - 执行：`意合虚拟机 → 三态逻辑`；`势调节 → 滚动规划 → 留白`
  - **双链（理论↔编程）**：技术选型/架构设计/复杂度/调试/接口设计等编程意象直接支撑对应方法论意象，
    使"辩证选型""关系编织梳理模块""留白管理不确定性"等决策由关系网自然涌现

## 四、YiHe 理论速览（包内已编码）

| 理论概念 | 一句话 | 编程场景映射 |
|---|---|---|
| 意合 | 意义在关系里，不在词本身 | 看模块先看依赖图而非单个类 |
| 关系编织 | 根据输入激活动态构建关系链 | 梳理复杂模块时织概念网找关键路径 |
| 激活扩散 | 激活沿关系网传播，半径 ≤3 度 | 定位缺陷时沿调用链扩散排查 |
| 语境场 | 语境决定意义，随境赋义 | 需求评审按当前语境澄清 |
| 势态推演 | 决策是倾向度而非对错值 | 方案评估看走向而非拍板 |
| 辩证推演 | 正反合，矛盾即动力 | 技术选型列正反合表 |
| 留白 | 不确定处显式留白不猜测 | 需求未定处标注假设 |
| 确认网关 | 暂停-确认-执行 | 高风险上线强制确认 |
| 学习闭环 | 采纳/拒绝回报→权重调整 | 评审意见沉淀为团队记忆 |
| 三态逻辑 | 成功/失败/待定，待定需收敛 | 不确定结论显式标三态 |
| 滚动规划 | 只看三步，逐步校验推进 | 任务拆分小步迭代 |
| 类比推理 | 类比经验库相似案例 | 新接口参照既有成熟接口 |

## 五、扩展定制

1. 复制 `pkg-dev.json` 为 `pkg-dev-<your>.json`，替换/增补意象与关系；
2. 遵守格式约束：`relations.from/to` 必须写**意象 content**（先列全 imagos 再写 relations）；
   引用不存在的意象，该关系会被静默跳过；
3. 重新导入（同命名空间=合并；同 id 导入=覆盖/增量合并）并激活即可。

## 六、治理与已知行为

- `yihe_admin op=audit`：追踪谁在何时 load/activate 了 pkg-dev；
- `yihe_feedback`：对决策采纳/拒绝回报，强化或弱化路径；
- **脚本匹配为词典语义匹配**：短关键词/场景词命中率高（如「辩证推演技术选型」命中 2）；
- **risk_tier=high** 触发确认网关（forced_pause），属预期安全行为；
- **need_more_info**：问题越具体、意象覆盖越窄时越常见，补充 input/context 领域词可提升决策率；
- 重启后按 `yihe-packs/README.md` 第六节 bootstrap 恢复。

## 七、执行层接入（yihe_exec 滚动执行，实测通过）

决策不只给建议，还能变成三步滚动计划逐步校验推进：

```text
1. yihe_reason → 得 decision_id（如 dec-805-49b0「辩证推演」）
2. yihe_exec op=plan decision_id=<id>        → 生成 3 步计划（plan_id 自动生成）
3. yihe_exec op=advance plan_id=<plan_id> step_result={step, ok, note}
   （注意：step 号在 step_result.step 里，非顶层参数）
   → 偏离自动回喂重生成（replan），通过则推进
4. yihe_exec op=report decision_id=<id> outcome=success|failed plan_id=<id>
   → 执行-认知闭环：成功强化选中路径，失败削弱并强化备选
```

实测（dec-805-49b0 辩证推演选型）：plan 3 步（辩证推演→技术选型→校验）
→ advance 第 1/2/3 步全部通过 → report success 入奖惩队列（1 条边）。

## 八、商业许可（pro）

- `pkg-dev` / `pkg-dev-ts` 已标记 `tier: pro, license_required: true`；
- 已加入运行插件与 Rust 网关的 `PRO_PACKS`（`['pkg-finance-pro','pkg-dev','pkg-dev-ts']`），
  **DSH 重启后生效**；
- 激活：`yihe_license op=activate pack_id=pkg-dev key=PRO-xxxx…`（≥8 位，PRO-/ENT- 前缀；
  ENT- 前缀升 enterprise、配额不限）；
- 计量：`yihe_license op=usage`（pro 配额 10000 次/月，超额 fail-closed 或 allow_over 计费）；
  `yihe_license op=export` 导出账单。

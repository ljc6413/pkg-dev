## 二、能力加速动作（本轮执行）

### 2.1 脚本预匹配短路（越用越省钱的核心闭环）

**机制**：`script_hit_threshold=0.5` 开启后，问题命中高分脚本 → 免 reason 直接返回脚本模板结论（0 token）。

**实测效果**：

| 阶段 | script_hit 次数 | 节省 |
|---|---|---|
| 短路开启前 | 0 | — |
| 开启后（基础场景） | 5 次 | ≈ 6000 token |
| **tags 增强后（本轮）** | **12 次** | **≈ 14400 token** |

reason 计量保持 **132 未增**，新增提问全部免费短路——"越用越省钱"从机制变成实测事实。

### 2.2 脚本 tags 同义词增强（命中率提升的关键）

对 11 个包的脚本补充**真实提问措辞**为 tags（如「分支策略怎么选」「CPU瓶颈怎么定位」「哈希还是二叉树」），使 `matchScripts` 关键词通道能识别用户实际问法：

- **12 个包**（git/perf/algo/evolve/bigdata/cpp/dotnet/game/arch/design/net/os）脚本 tags 全面增强
- **已实测**：8 个之前不命中的真实提问全部命中短路（冲突解决/数据结构选型/性能指标/IO模型/架构风格/内存安全/协议选型/引擎选型）

### 2.3 知识缺口检测（auto-expand）

27 包分析：缺口指数 1514，3143 条候选补丁。发现大量"低连接"意象（语言基础概念），
是**设计使然**（基础节点被少数核心关系引用）而非缺陷；但提示后续可补充概念间的语义关系
提升推演质量。

## 四、加速建议（下一步）

### 4.1 高频领域深挖（GIT/ALGO/PERF 各补 2-3 场景）
对高频使用领域，将**已实测的决策问题**固化为脚本（如 GIT「提交规范怎么用」「怎么回滚」）。
方法：`node self-learn.mjs` 看高置信决策 → 转脚本 → 补提问同义词 tags。

### 4.2 开启反馈闭环（最大瓶颈）
当前反馈 **0 条**——学习闭环没有数据。建议：
```
每次 reason 后：yihe_feedback decision_id=<id> outcome=adopted/rejected
```
反馈会调整关系权重（奖惩队列），让正确路径更易命中，错误路径衰减。

### 4.3 决策缓存（省 token 第二通道）
对高频同题（如"这个模块要不要重构"反复问）启用决策缓存：相同 question 二次命中直接复用
结论。当前脚本短路已覆盖大部分，缓存可作为兜底。

### 4.4 月度进化循环
```
1. self-learn.mjs → 沉淀建议脚本化
2. token-save.mjs → 看本地化率趋势（省钱进度条）
3. auto-expand.mjs → 缺口分析 → 补关系
4. evolve-share.mjs → 导出增量共享
```
